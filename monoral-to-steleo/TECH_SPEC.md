# モノラル → ステレオ空間化プラグイン 技術選定・要件

## 1. 目的
マイクで録ったモノラル音声(声・楽器)は、ステレオの真ん中に1本で固まる。
このプラグインで、左右に自然に広がる「空間のあるステレオ」にする。
用途を「モノラル素材のステレオ化」だけに絞る。リバーブなど他の機能は入れない。

## 2. できるか
できる。仕組みは単純で、同じ音に左右で少し違う処理をかけて、左右の差を作る。
差が大きいほど、聞こえる幅が広がる。

## 3. 環境確認の結果(この Mac)
| 項目 | 状態 | 影響 |
|------|------|------|
| CPU / OS | Apple Silicon (arm64) / macOS 27.0.1 | arm64 でビルドする |
| DAW | Cubase 13 | **VST3 形式が必須**。Cubase は AU 非対応 |
| Xcode | Command Line Tools のみ | フル版 Xcode のインストールを推奨 |
| cmake | 未インストール | `brew install cmake` が必要 |
| git / clang | あり | そのまま使える |

## 4. 技術選定

### フレームワーク: JUCE (C++) を推奨
- プラグイン開発の標準。VST3 / AU を同じコードから出力できる。
- GUI(つまみ)、パラメータ保存、DAW 連携が最初から揃う。
- ビルドは CMake で行う。
- ライセンス: 個人利用・配布は無料枠や AGPL の範囲で可能。販売する場合は商用ライセンスを確認する。

### 他の候補
| 候補 | 長所 | 短所 | 判断 |
|------|------|------|------|
| JUCE | 情報が多い、UI も作れる | C++ の知識が要る | **採用** |
| iPlug2 | 軽量 | 情報が少ない | 見送り |
| Faust | DSP を短く書ける | UI やビルドの自由度が低い | 見送り |
| Cmajor | 新しく書きやすい | 事例が少ない | 見送り |

### 出力形式
- VST3(Cubase 用)を最優先。
- AU は後から追加できる(Logic や GarageBand を使う場合)。

## 5. 空間化の方式(DSP)
次の3つを組み合わせる。

1. **Haas 効果(短い遅延)**: 片側を 5〜30 ms 遅らせると、音が遅らせた側と反対に広がって聞こえる。
2. **デコリレーション(オールパスフィルタ)**: 左右で位相の回り方を変え、音色をあまり変えずに左右の差を作る。
3. **わずかな揺らぎ(コーラス的モジュレーション)**: 遅延時間をゆっくり揺らし、広がりを自然にする。

仕上げに **Mid/Side 処理**で、広がり(Side)の量を調整する。

### 注意点
- 遅延を大きくしすぎると、モノラル再生時に音が薄くなる(コムフィルター)。
  - 対策: Mix の上限を設ける、モノラル確認ボタンを付ける。
- 低音は広げない。低域(約150 Hz 以下)は中央に残す(Bass Keep)。
  - 低音が左右に散ると、スピーカーで迫力がなくなる。

## 6. パラメータ案(どのくらい左右に振るか)
| 名前 | 範囲 | 初期値 | 役割 |
|------|------|--------|------|
| Width | 0〜200 % | 100 % | 全体の広がり量 |
| Spread Time | 1〜40 ms | 15 ms | 左右の遅延差 |
| Decorrelation | 0〜100 % | 50 % | オールパスによる左右差の量 |
| Motion | 0〜100 % | 20 % | 揺らぎの量 |
| Bass Keep | 50〜300 Hz | 150 Hz | これ以下は中央に固定 |
| Center Level | -12〜+6 dB | 0 dB | 中央の音量(広げても声が埋もれないように) |
| Mix | 0〜100 % | 100 % | 原音との混ぜ具合 |
| Mono Check | ON/OFF | OFF | モノラル再生での聞こえ方を確認 |

プリセット案: Subtle(自然)/ Wide(広め)/ Dreamy(空間系)。

## 7. 動作要件
- 入力: モノラル(ステレオトラックに置かれた場合は L+R を合算してから処理)
- 出力: ステレオ
- 処理遅延: 数 ms 以内(遅延補正をDAWに通知)
- CPU 負荷: 軽く、1 トラックで 1% 未満
- ビルド: macOS arm64、VST3(後で AU)

## 8. 開発の進め方
1. 環境準備: Xcode、cmake、JUCE を入れる
2. 骨組み: 何もしないプラグインをビルドし、Cubase で読み込めることを確認
3. DSP 実装: Haas → オールパス → 揺らぎ → Mid/Side の順に追加
4. UI: つまみとモノラル確認ボタン
5. 試聴調整: 実際の声で音を聴き、初期値とプリセットを決める
6. 配布準備: コード署名と公証(他の Mac に配る場合のみ。自分の Mac だけなら不要)

## 9. 確認したいこと
- 主な素材は声ですか、楽器ですか。
- 他の Mac や他人に配る予定はありますか。
- Cubase 以外の DAW も使いますか(AU が必要かどうか)。
- 広がりは「自然」寄りと「派手」寄りのどちらが好みですか。

## 10. 追加機能: イコライザー(仮仕様・要確認)
参考イメージ: Waves の「9点」で調整するタイプの EQ(製品名は要確認。Q10 などが候補)。
特定製品のコピーではなく、操作感を似せたオリジナル実装にする。

- 実装: JUCE の `juce::dsp::IIR` フィルターを使う
- バンド数: **最大 32 点のスプライン EQ(確定。詳細は第13章)**
- 構成: 第13章を参照
- 各バンドの設定: 第13章を参照
- 画面: 周波数特性のグラフを表示し、点をドラッグして調整する
- 処理順: EQ → ステレオ化(Width など)。モノラルのうちに音色を整えてから広げる
- CPU 負荷: 9 バンドでも軽い(1 トラックで数 % 未満の見込み)
- 追加工数: UI の作り込みが主で、DSP 自体は小さい。開発手順の「4. UI」に含める

## 11. 開発方針: 標準ライブラリを優先する
自作は最小限にし、実績のあるライブラリを使う。

| 機能 | 使うもの |
|------|----------|
| プラグイン本体 / VST3 / AU / UI / パラメータ保存 | JUCE |
| EQ(各バンドのフィルター) | `juce::dsp::IIR` / `juce::dsp::ProcessorChain` |
| 遅延(Haas 効果、揺らぎ) | `juce::dsp::DelayLine` |
| 揺らぎ(LFO) | `juce::dsp::Oscillator` |
| 低域を中央に残す分割 | `juce::dsp::LinkwitzRileyFilter` |
| オールパス(デコリレーション) | `juce::dsp::IIR`(オールパス係数) |
| 音量・ゲイン・Mix | `juce::dsp::Gain` / `juce::dsp::DryWetMixer` |
| パラメータ管理 | `juce::AudioProcessorValueTreeState` |
| ビルド | CMake(JUCE 付属の `juce_add_plugin`) |
| プリセット | JUCE の状態保存(XML)で保持 |
| EQ のグラフ表示 | `juce::dsp::IIR::Coefficients::getMagnitudeForFrequency` で特性を計算 |

JUCE に無い機能が必要になった場合のみ、別のライブラリを検討する。

## 12. 開発フレームワークとコード方針(読みやすさ・デバッグ重視)

### フレームワーク
- アプリ全体の枠組みは JUCE の標準構成を使う(`AudioProcessor` / `AudioProcessorEditor` / `AudioProcessorValueTreeState`)。独自の仕組みは作らない。
- JUCE のサンプルプロジェクト(AudioPluginDemo など)の構成に合わせる。
- ビルドは CMake 1本にする。

### コード方針
- 処理を機能ごとにファイルとクラスに分ける。1クラス1役割にする。
  - `EqProcessor` : EQ
  - `StereoWidener` : 左右への広げ処理
  - `BassKeeper` : 低域を中央に残す処理
  - `PresetManager` : プリセットの保存と読み込み
  - `PluginProcessor` : 上記をつなぐだけ
- 名前は省略せず、意味が分かる英語にする(`hpf` ではなく `highPassFilter`)。
- 数値の直書きをしない。値には名前を付ける(`constexpr float maxHaasDelayMs = 40.0f;`)。
- パラメータ名・範囲・初期値は1つのファイル(`Parameters.h`)にまとめる。
- コメントには「何をしているか」ではなく「なぜそうしているか」を書く。
- 処理の順番は `PluginProcessor::processBlock` の中で読める形にする(EQ → 低域分離 → 広げ処理 → Mix)。
- 関数は短く保ち、ネストは浅くする。

### デバッグしやすくする仕組み
- 各処理を個別に ON/OFF できるバイパスを付ける(どの処理が原因か切り分けるため)。
- Mono Check ボタンで、モノラル再生時の聞こえ方を確認できる。
- Debug ビルドでは、入出力レベルや現在のパラメータ値をログに出す(`DBG()` を使用)。
- 音声処理スレッドの中では、メモリ確保・ログ出力・ロックをしない。ログ表示は別スレッドで行う。
- テストは JUCE の `UnitTest` を使い、処理の入出力を確認する。
  - 例: モノラル入力の L と R が Width 0% で一致する、EQ のゲイン 0 dB で入力と出力が同じになる。
- ホスト互換の確認には `pluginval`(プラグイン検証ツール)を使う。
- スタンドアロン版も出力し、DAW を立ち上げずに動作を確認できるようにする。

## 13. 確定事項: 32バンド EQ とマイク別プリセット

### 13.1 EQ の構成: Voxengo CurveEQ 型(スプライン EQ)
参考: Voxengo CurveEQ(https://www.voxengo.com/product/curveeq/)。
「32」は **32 点**(コントロールポイント数)と解釈して更新した。前の「32 本スライダー」案は取り下げる。
製品のコピーではなく、操作感を似せたオリジナル実装にする。

#### 操作(CurveEQ に合わせる部分)
- グラフ上に点を打ち、点をなめらかにつないだ曲線(スプライン)がそのまま EQ カーブになる。
- 点は最大 32 個。クリックで追加、ドラッグで周波数とゲインを移動、ダブルクリックまたは右クリックで削除。
- 曲線を見ながら調整できる(WYSIWYG)。
- 入力または出力のスペクトラム(FFT 表示)を同じグラフに重ねる。
- 位相モード切り替え: Linear Phase / Minimum Phase。
- 調整幅: ±12 dB(初期案。後で変更可)、周波数 20 Hz〜20 kHz(対数軸)。

#### 実装(JUCE 標準のものを使う)
| 機能 | 使うもの |
|------|----------|
| スプライン補間 | 自作は短い(Catmull-Rom または Monotone cubic)。標準ライブラリに該当なし |
| カーブ → フィルター変換 | カーブから周波数特性を作り、`juce::dsp::FFT` で逆変換してインパルス応答(IR)にする |
| Linear Phase | 対称な IR を作り、`juce::dsp::Convolution` で適用(処理遅延あり。DAW に遅延を通知する) |
| Minimum Phase | カーブから最小位相の IR を作り、同じく `juce::dsp::Convolution` で適用 |
| スペクトラム表示 | `juce::dsp::FFT` と `juce::dsp::WindowingFunction` |
| 点の保存 | `AudioProcessorValueTreeState`(点の座標をパラメータ化)またはその ValueTree |
| グラフ描画 | `juce::Component` と `juce::Path` |

#### 補足
- スプライン補間だけは自作になる(約 50 行。単独のクラスにしてテストする)。
- 低域のカットは、点を下げることでも実現できる。
- マイクプリセットは、点の座標一覧として持つ(13.2 参照)。

### 13.2 マイク別プリセット
- 対象マイク: Shure SM58 / Shure SM7B / Neumann U87 / Audio-Technica AT2020 / Rode NT1
- 位置づけ: 各マイクの公開されている周波数特性と、一般的に言われる特徴をもとにした **初期値(目安)**。マイクの音を再現するものではない。
- 使い方: 録音した声に合わせて微調整する出発点にする。
- 作り方:
  1. 各メーカーの公式仕様書から周波数特性のグラフを調べ、特徴(近接効果、プレゼンスの山、高域の伸び)を整理する。
  2. 特徴を整えるための補正カーブを、ゲイン(dB)の表にする。
  3. 実際の声で聴いて、不自然な箇所を直す。
- 各プリセットに含める設定: EQ の点の座標(最大 32 点)、Width、Spread Time、Bass Keep など。
- 保存形式: XML。後から自分でプリセットを追加できるようにする。

| プリセット | 整える方針(初期案) |
|------------|---------------------|
| SM58 | 近接効果で膨らむ低域を抑え、こもりを減らす。高域の抜けを少し補う |
| SM7B | 出力が小さく高域がおとなしいので、中高域の明るさを補う |
| U87 | 元々バランスが良いので補正は小さく。低域の整理と空気感の補強 |
| AT2020 | 高域のきつさを抑え、低域の薄さを補う |
| NT1 | 高域の硬さを和らげ、中域に厚みを出す |

※ 具体的な dB の値は、仕様書を確認して実装時に決める。この表の方針は、現時点での目安。
